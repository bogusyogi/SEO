# Dashboard snapshot exporter

`python scripts/dashboard_export.py --portfolio PATH --performance-reports PATH --output PATH` creates schema version 1 JSON for the dashboard. Portfolio roots are read from `portfolio.json`; each root contributes only normalized `.seo` evidence. Performance folders matching `performance-baseline-*` or `performance-weekly-*` are supported, with a same-name `.psi.json` sidecar taking precedence.

Provider failures remain visible at newest observation timestamp. Missing values are `null`; measured empty GSC aggregates can be zero, while empty successful Bing observations are `no_data`. Output is allowlisted, redacted, UTF-8, and atomically replaced only after complete JSON serialization.

Optional detail fields preserve schema version 1. `site.audit` adds `response_health_score` (computed only when every crawled page has an observed HTTP status), `response_health_basis`, unique `affected_urls`, and capped `redirects`, `broken`, and `blocked` URL samples. `site.performance.vitals` contains `lab` (`lcp_ms`, `cls`, `tbt_ms`) and `crux` (`lcp_ms`, `inp_ms`, `cls`), with `null` for unavailable raw values. `site.details` appears only when local reports exist: `provider` mirrors allowlisted GSC, GA4, indexing, backlink, and domain-rating detail rows, `imported_links` contains sanitized GSC link rows and coverage, `ahrefs_observed` keeps manual Ahrefs overview observations separate from native crawl evidence, and optional `readiness` exposes the validated per-site route map. When newer provider GSC evidence exists, top-level `site.gsc.metrics` and `date_range` use its current aggregate while `site.gsc.previous` and query changes remain available in details. Provider periods and prior/current change rows remain source-provided; absent or failed observations remain visible as status plus `null` fields.
